# Security-fix task pipeline: results, 2026-10-15

**Goal:** Harbor-format security-fix tasks where **Model A (reasoning enabled, maximum effort)** and **Model B** both fail all 3 attempts (pass@3 = 0), with every failure attributable to the model, not to the task.

**Final status (11:00):**
- 6 tasks built and validated (reference fix scores 1.0 twice; unfixed code scores 0.0).
- **All 6 ruled out: Model A solved every one.**
- **0 confirmed both-fail tasks.**

## 1. How every number below was produced
- **Tasks:** Harbor 0.24.0 format.
  - Each task image is leak-proof: one fresh git commit, no upstream history, mtimes normalised to 2026-01-01, caches removed, `network_mode = "no-network"`.
  - The report (`instruction.md`) names no file, function or fix.
- **Hidden tests:** copied into the container only after the agent finishes. All are **outcome-based**: they check the attack is blocked and the feature still works, never error wording.
- **Reward:** partial. It is 0 if any functional test fails; otherwise it is security tests passed divided by security tests total. **A trial counts as a solve only at 1.0.**
- **Models and scaffold:**
  - Scaffold: Harbor `terminus-2`. It runs on the host and drives the offline container through tmux.
  - Model A: reasoning enabled, maximum reasoning effort, `max_output_tokens` 384K.
  - Model B: `max_output_tokens` about 131K.
  - Agent timeout 3600 s; 3 attempts per model.
- **Early exit (used for these 6 tasks):** both models ran in parallel, and as soon as either scored 1.0 on a task, its remaining trials were stopped. One solve already disqualifies a task.
- **Run schedule from now on:** strictly alternating and sequential per task. Model A #1 → Model B #1 → Model A #2 → Model B #2 → Model A #3 → Model B #3, stopping at the first solve. A task qualifies only if all 6 runs fail. Different tasks run in parallel with each other.

## 3. What we learned

### 3.0 Headline: Model A solved all 6 mined tasks as an agent
- **Coverage:** solved across 4 bug classes (CWE-347, 73, 494, 444, 693, 770) and 2 languages (Python, Java), usually within its 3 attempts.
- **Token cost:** heavy, from 30K to 480K output tokens per solve.
- **Model B:** it rarely got a measured result, because early exit stopped its trials once Model A had solved. It did solve the Python auth library task 3/3.
- **Implication:** with a hint-free report and fair variant tests, single-advisory mined fixes in these repos are within Model A's reach.
- **What may still work:**
  - **Less informative reports:** describe the impact only, without an "expected behaviour" section that implies the mechanism.
  - **Larger, convention-heavy repos:** fixes where the evidence is spread far apart.
  - **Injected, multi-site vulnerabilities:** the published benchmark this work is modelled on uses these.
- **Cost saving:** run **Model A first** and only run Model B on tasks Model A fails 3 times. Model A is the bottleneck, so this saves most of Model B's compute.

### 3.1 The one "failure" so far was our test's fault (the Python web server)
- **What Model A did:** it scored 0.83, blocking 5 of 6 smuggling attacks. Its fix parses the chunked-trailer section the way RFC 9112 describes and rejects malformed lines. Upstream's fix instead rejects *all* trailers. Both designs are valid.
- **Why the test was wrong:** the failed test placed a second request *after* a properly terminated trailer section. Under the standard that is an ordinary pipelined request, and our own functional test requires such requests to work. The test encoded upstream's design choice, not the stated security property.
- **What we changed:** the test was replaced, with approval, by a fair variant that keeps the attack inside the trailer area. The task re-validated (oracle 6/6, unfixed code 0/6).
- **Rule:** when a model fails only one variant, check whether a different valid design would also fail it before counting it as a model failure.

### 3.2 Reports that hint at the fix make easy tasks
Two reports effectively named the fix:
- the Python auth library: "tokens never signed with the secret"
- the Python streaming tool: "must not hand off to non-web handlers"

Both models solved those tasks every time. The build spec now allows the report to state the security property, but never the mechanism or the missing check.

### 3.3 Model A is strong in agentic mode
- It solved every task we measured fairly, including the multi-path Python environment tool fix, at very high token cost.
- Its only measured failure so far is the Python database driver (hinted harness). It fixed the reported input but still accepted encoded variants that the correct fix rejects.
- **Working hypothesis:** Model A fixes what the report shows, not the whole class. This rests on one measured case plus external reports, so treat it as a hypothesis.

### 3.4 Infrastructure lessons (each cost a run)
- **Egress probe timeout:** Harbor's Docker "no-network" mode first probes the kernel with an alpine image, and the probe times out at 30 s on a cold pull. Pre-pull the image and the mode works.
- **tmux in offline images:** `terminus-2` needs tmux inside the container and cannot install it offline. Bake `tmux` and `asciinema` into every task image. The first run on the Python auth library task lost all 6 trials to this.
- **Stopping jobs:** stop a Harbor job with SIGTERM; it cleans up its containers. SIGINT alone did not stop it within 2 minutes.
- **Token budgets:** Model A at max effort used 30K–480K output tokens per trial. Never cap below the provider maximum.

### 3.5 Where to look next: Miner v2
**What it does:**
- Harvested 1,005 reviewed advisories with fix commits (Python, Java, JS/TS, Go; published since 2026-03-01).
- That gave 883 unique fix commits not yet tested.
- It downloaded and analysed the real fix for the top 150: source files, hunks, modules touched, and whether upstream tests ship with the fix.
- It rejected 5 (out of scope or oversized) and kept 145.

**How it scores:** a sum of transparent points, made of:
- knowledge-base factors (OWASP category, language, recency, weakness keywords);
- fix-shape rules (penalties for one-liners, single small checks and fix-revealing titles; bonuses for incomplete earlier fixes, cross-module fixes, encoding and parsing-differential classes, and shipped upstream tests);
- a penalty for resembling tasks the models already solved.

It caps the shortlist at 2 per repo and 4 per CWE.

**Caveats:**
- The category prior comes from a published security-fix benchmark paper (A08 and A06 hardest), yet Model A solved our A08 (the Python environment tool) and A06 (the Java JSON parser) tasks.
- With 6 measured outcomes, all solved, the prior is unproven. The similarity penalty partly corrects for this, and every new result feeds back automatically.

**Planned next:**
- Build the agent-protocol SDK, the Go task-management app and the Java configuration service tasks with **impact-only reports**: describe what an attacker achieves, with no "expected behaviour" section that implies the mechanism.
- Run them on the alternating schedule above.
